## Chapter 1 — 2026-05-07 — Initial bootstrap
**Time marker:** 2026-04-22..2026-05-07
**Assets introduced:** internal/forest/forest.go, internal/forest/tree.go, internal/forest/node.go, internal/gate/gate.go, internal/tfidf/engine.go, internal/text/canonicalize.go, docs/sliding-window-intent-forest.md
**Interests:** TF-IDF classification, decay scoring, pruning with peak-score rescue, bubble-up abstraction, cluster merging, typo tolerance
**Topics:** intent classification actions, TF-IDF cosine similarity, session boundary frequency halving, min-heap-based pruning

### What
Each prompt is tokenized, stemmed, typo-canonicalized, and TF-IDF vectorized. Cosine
similarity against every leaf and root in the forest produces one of five actions:
ActionNew (no close tree, start one), ActionBranch (close to a tree but not a leaf,
fork off the root), ActionExtend (close to a leaf, append as child), ActionContinue
(terse continuation of the last tree), or ActionSkip (terse with no tree to continue).
Tree scores decay exponentially with age. Pruning fires when nodeCount exceeds
memorySize and uses a min-heap on decay-weighted scores to evict the lowest-scoring
leaves. Trees with a high historical PeakScore can be rescued from prune even when
their current score is low — a once-hot topic doesn't disappear just because it's
cooling. Cluster merging fuses two trees whose roots cosine-match above
mergeSimilarity. Bubble-up regenerates parent abstractions bottom-up using
presence × IDF over child tokens, so the root content stays representative as new
leaves arrive. Session boundaries (configurable timeout) halve frequencies so a
Monday-morning session doesn't get evicted by Friday-afternoon work.

### Why
Pruning by current score alone would lose topics that mattered briefly but intensely;
PeakScore preserves them. Bubble-up keeps the root abstraction stable enough that
returning to a topic days later still classifies as ActionExtend rather than
ActionNew, which is what makes "the trail itself" durable. Typo canonicalization
(Levenshtein with bigram pre-filter potential) prevents trivial typos from spawning
sibling trees that should have merged. The five-action classification is finer than
"is this related" — ActionContinue handles "yes" / "do that" follow-ups that have
no useful TF-IDF signal of their own; ActionSkip drops them silently rather than
letting them spawn empty trees.
