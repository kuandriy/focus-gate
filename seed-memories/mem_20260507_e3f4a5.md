## Chapter 1 — 2026-05-07 — Initial bootstrap
**Time marker:** 2026-05-04..2026-05-07
**Assets introduced:** internal/memory/commit.go, internal/memory/promote.go, internal/memory/candidate.go, internal/memory/pending.go
**Interests:** LLM-mediated review, structured commit JSON, retry budget, aggregate index without bodies
**Topics:** candidate to memory promotion, append create discard decision, structured validation errors, retry loop with budget

### What
When a tree about to prune passes the candidate floors (minLeaves, minPrompts,
refs-or-guide presence, weighted score), it's snapshotted into pending_memories.json.
The user runs `fg: memory promote [tempId]`, which emits a Stage B prompt: a
candidate snapshot (reason, abstraction, refs, top terms, node contents) plus the
aggregate index of every memory across every enabled source — titles + indexes
only, no bodies — plus the JSON schema for `fg: memory commit`. The LLM replies
with `fg: memory commit <tempId> '<json>'` carrying `action ∈ {append, create,
discard}`. Validation produces structured `{field, reason, hint}` errors; on
failure the candidate's CommitRetries counter increments and the LLM gets up to
`memory.commitRetries` (default 2) attempts before the candidate parks in pending
with a user-facing note. Append routes to AppendChapter on the target memory in
the resolved source; create routes to WriteFile in the chosen source (defaulting
to the registry's `default` when targetSource is omitted); discard removes the
candidate from pending without writing.

### Why
The LLM is a student, not a transcriber: skills, code, docs are inputs to learn
from, not source-of-truth recipes to copy. Showing the aggregate index without
bodies forces the decision to be about overlap of interests/topics/assets/
timeMarkers rather than near-duplicate body text — the LLM has to *reason* about
fit rather than pattern-match. Structured commit JSON eliminates parse ambiguity
and gives the LLM a small surface to fix when validation fails; the retry loop is
intentionally small because persistent failures usually indicate a deeper
schema/content mismatch that warrants a human eye, not more LLM rounds. The same
loop runs in bootstrap sessions (per SHARED_MEMORY_PLAN §7) — promotion at runtime
and bootstrap from skills/code/docs share one decision shape.
