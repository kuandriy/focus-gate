## Chapter 1 — 2026-05-07 — Initial bootstrap
**Time marker:** 2026-05-04..2026-05-07
**Assets introduced:** internal/memory/surface.go, internal/memory/manifest.go, internal/memory/multi_source.go, internal/text/refs.go
**Interests:** tier-weighted scoring, inverted indexes, multi-source composition, asset extraction
**Topics:** per-prompt memory surfacing, max-combine across tiers, ByAsset ByInterest ByTopic, prompt asset extraction

### What
On every prompt, surface scores each candidate memory across four tiers and takes
the max:

  final = max(
    asset_score    × W.asset,        // exact match against extracted file paths + endpoints
    topic_score    × W.topic,        // cosine(prompt_vec, vec(topic.name)) × topic.weight
    interest_score × W.interest,     // cosine(prompt_vec, vec(interest.name)) × interest.weight
    fingerprint_score × W.fingerprint // cosine(prompt_vec, memory.fingerprint)
  )

Default weights are 1.0 / 0.8 / 0.6 / 0.4. Memories above surfaceThreshold are
sorted by final score; the top-K render as a pointer block with a framing line,
the dominant tier annotation (`via asset` / `via topic`/etc.), and the matched
reasons. The MultiSourceIndex composes manifests from every enabled source so the
surface scan spans personal + shared corpora in one pass; Touch increments
propagate back to the owning manifest for end-of-prompt save. Inverted indexes
(ByAsset, ByInterest, ByTopic) are populated by Rebuild for fast traversal —
no body parsing on the prompt path. Asset extraction is phased: file paths first
(via `ExtractFilePaths`), HTTP endpoints (`POST /...`) second (via
`ExtractEndpoints`), env vars and function-name patterns deferred.

### Why
Asset hits are the highest-confidence signal — the user typed a file path or
endpoint that the memory actually touched, so the memory is almost certainly
relevant. Topic and interest cosine catch semantic matches that exact extraction
misses. Fingerprint cosine is the fallback. Max-combine (rather than sum) means
tier weights are about *priority* rather than *additivity*: a perfect asset match
beats a weak match in any other tier, but a strong topic match still surfaces
when no asset hits. The "no body parsing on the prompt path" invariant is what
makes the hot path cheap enough to run on every prompt — bodies are read only
when the AI Read-tools the file the surface block points at.
